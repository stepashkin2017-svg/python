Что такое наследование

Наследование встречается не только в программировании. Мы каждый день говорим так в жизни — просто не замечаем.

Примеры из жизни

Что говоримЧто не уточняем

Компьютерная игра жанра RPGэто программа — у неё есть окно, она работает на компьютере
Автомобильэто транспорт — у него есть колёса и мотор

🧠 Что мы имеем в виду

Когда мы говорим «кошка», мы не перечисляем снова, что она животное. Мы просто опираемся на то, что про животных уже известно.

То же и в программировании: сказали «Рыцарь — это Герой» — и не нужно заново описывать здоровье, силу, броню.

Суперкласс (родительский класс)
Это класс, от которого наследуют. Он содержит общие свойства и методы для нескольких классов.
В нашем примере Hero — суперкласс. Он описывает то, что есть у любого героя.
Класс-наследник (подкласс)
Это класс, который берёт всё у суперкласса и дополняет своими свойствами или методами.
Warrior — наследник Hero. Он умеет всё, что умеет Hero, плюс атакует мечом.
⚠️ Как читать схему

Стрелка всегда идёт от наследника к родителю — «Рыцарь является Героем». Не наоборот! Герой — не обязательно рыцарь.

Можно проверить фразой: «Warrior — это Hero»? Да. «Hero — это Warrior»? Нет. Значит, наследование правильное.

Как объявить класс-наследник

Оказывается, для этого нужно изменить всего одну строчку. Вместо пустых скобок — написать имя суперкласса.

Сравним

# Обычный класс — без наследования class Hero(): ... # Класс-наследник от Hero class Warrior(Hero): ...

Разница только в том, что в скобках стоит имя Hero. Всё! Теперь Warrior знает всё, что знает Hero.

Разбираем строку по частям

class Warrior ( Hero ):
class Ключевое слово. Объявляем новый класс. Как всегда.
Warrior Имя нового класса-наследника. Придумали сами.
(Hero) В скобках — имя суперкласса. Говорим Python: «Warrior берёт всё у Hero».
🧠 Что значит «берёт всё»

Warrior получает все свойства и все методы класса Hero. Как будто они записаны прямо внутри Warrior.

А ещё внутри Warrior можно добавить то, чего нет у Hero. Например, свой метод.

Три важных правила

1 Класс-наследник не копирует код родителя. Он на него ссылается. Если родитель изменится — это увидят все наследники.
2 Внутри наследника можно добавлять новые методы и свойства, но нельзя «стереть» родительские.
3 В круглых скобках можно указать только один родительский класс для наших задач (в Python бывает и несколько, но это уже высший пилотаж).

Warrior и Mage — на практике

Соберём первую программу с наследованием. Сначала — базовый класс Hero, а потом два наследника с новыми методами.

Суперкласс Hero

class Hero(): def __init__(self, name, health, armor): self.name = name self.health = health self.armor = armor def print_info(self): print('Имя:', self.name) print('Здоровье:', self.health) print('Броня:', self.armor)

Наследник Warrior

Рыцарь отличается от обычного героя тем, что умеет здороваться и бить мечом. Добавим эти два метода. Никаких новых свойств — значит, свой конструктор не нужен.

class Warrior(Hero): def hello(self): print('Верхом на коне появился воин!') self.print_info() def attack_sword(self, enemy): print('Храбрый воин атакует мечом!') enemy.health -= 15 print('У', enemy.name, 'осталось', enemy.health, 'здоровья')

Наследник Mage

class Mage(Hero): def hello(self): print('Волшебник спустился с башни!') self.print_info() def cast_spell(self, enemy): print('Маг произносит заклинание!') enemy.health -= 25 print('У', enemy.name, 'осталось', enemy.health, 'здоровья')

Когда нужны новые свойства

Пётр снова пишет: у Рыцаря и Мага должно быть разное оружие, а у дракона — магия. Это уже новые свойства, которых у Hero не было.

🤖
Я попробовал добавить новое свойство. Написал в Warrior конструктор со свойством weapon. Но при запуске программа пожаловалась: «Конструктор родителя не вызван». Что-то не так…

Вот что сделал Байт:

class Warrior(Hero): def __init__(self, name, health, armor, weapon): self.weapon = weapon # только новое свойство!

И что получилось:

Ошибка при запуске
warrior = Warrior('Ричард', 100, 50, 'меч')

AttributeError: 'Warrior' object has no attribute 'name'
                 'Warrior' object has no attribute 'health'
                 'Warrior' object has no attribute 'armor'
🚨 Что случилось

Мы написали свой конструктор __init__ в классе Warrior. И теперь Python не вызывает родительский — потому что наследник сказал: «у меня теперь свой, не трогай родительский».

Нужно явно попросить родителя выполнить его конструктор. Для этого существует специальный метод super(). Сейчас с ним познакомимся.

Волшебное super()

super() — это способ обратиться из класса-наследника к его родителю. Обычно его используют, чтобы вызвать родительский конструктор.

super()
Это команда, которая возвращает ссылку на суперкласс из текущего класса-наследника. С её помощью можно обратиться к методам родителя, как будто они наши.
super().__init__(...) — «вызови конструктор родителя и передай туда эти аргументы».

Как это работает

🛡️ Warrior.__init__
→
super().__init__(...)
→
🏰 Hero.__init__
Мы говорим из наследника: «родитель, выполни свой конструктор и заполни общие свойства — name, health, armor».

Правильный код Warrior

class Warrior(Hero): def __init__(self, name, health, armor, weapon): super().__init__(name, health, armor) self.weapon = weapon def show_weapon(self): print('Оружие:', self.weapon)
🧠 Разбор строки за строкой

1. def __init__(self, name, health, armor, weapon): — в скобках все параметры: и родительские, и новое weapon.

2. super().__init__(name, health, armor) — передаём родителю только то, что он умеет принимать. Родитель создаёт свойства name, health, armor.

3. self.weapon = weapon — добавляем своё новое свойство.

⚠️ Частая ошибка новичка

Написать super().__init__(name, health, armor, weapon) — передать родителю лишний аргумент. Родитель не знает, что такое weapon, и выдаст ошибку.

В super().__init__(...) передаём только те параметры, которые есть у родителя.

Три способа записать super()

ЗаписьЧто делает
super().__init__(...) Вызвать родительский __init__. Самый частый случай.
super().print_info() Вызвать родительский метод print_info.
Hero.__init__(self, ...) То же самое, но по имени класса. Так уже не пишут — используй super().

Полный пример: Warrior и Mage с новыми свойствами

class Hero(): def __init__(self, name, health, armor): self.name = name self.health = health self.armor = armor def print_info(self): print('Имя:', self.name) print('Здоровье:', self.health) print('Броня:', self.armor) class Warrior(Hero): def __init__(self, name, health, armor, weapon): super().__init__(name, health, armor) self.weapon = weapon def show_weapon(self): print('Оружие:', self.weapon) class Mage(Hero): def __init__(self, name, health, armor, magic): super().__init__(name, health, armor) self.magic = magic def show_magic(self): print('Магия:', self.magic) # Проверяем w = Warrior('Ричард', 100, 50, 'меч') w.print_info() w.show_weapon()

Sprite — наследник Turtle

Сейчас мы применим наследование к модулю turtle. Оказывается, можно создать свой класс-наследник Turtle и добавить ему новые свойства и методы.

🤖
Мы с Байтом хотим написать игру. В ней будет несколько объектов, которые двигаются по экрану. У черепашки есть всё, что нужно для рисования, но нет свойства «шаг». Придётся его добавить — а значит, написать свой конструктор.

Что мы хотим добавить

➕ Новое свойство step — на сколько пикселей двигается объект за один шаг.
➕ Методы move_up, move_down, move_left, move_right — двигаться по стрелкам.
➕ Метод is_collide(sprite) — проверять, столкнулся ли с другим спрайтом.

Класс Sprite

from turtle import * class Sprite(Turtle): def __init__(self, x, y, step=10, shape='circle', color='black'): super().__init__() # создаём черепашку self.penup() self.speed(0) self.goto(x, y) self.color(color) self.shape(shape) self.step = step # новое свойство! def move_up(self): self.goto(self.xcor(), self.ycor() + self.step) def move_down(self): self.goto(self.xcor(), self.ycor() - self.step) def move_left(self): self.goto(self.xcor() - self.step, self.ycor()) def move_right(self): self.goto(self.xcor() + self.step, self.ycor())
🧠 Разбор

1. class Sprite(Turtle): — Sprite наследует от Turtle. Значит, у него уже есть все черепашьи методы: goto, color, shape и другие.

2. Мы написали свой конструктор, чтобы добавить step. Внутри конструктора сначала вызываем super().__init__() — создаём черепашку как обычно. Потом настраиваем её и добавляем step.

3. Методы move_up и другие — используют унаследованные goto, xcor, ycor.

💡 Значения по умолчанию

В конструкторе стоит step=10, shape='circle', color='black'. Это значит, что если мы не укажем эти параметры — Python подставит их сам.

Поэтому можно написать и Sprite(0, 0), и Sprite(0, 0, 20, 'square', 'red') — оба варианта сработают.

Создаём спрайты

# Игрок — зелёный треугольник внизу player = Sprite(0, -100, 10, 'triangle', 'green') # Цель — синий круг сверху goal = Sprite(0, 150, 0, 'circle', 'blue') # Препятствие — красный квадрат enemy = Sprite(-100, 0, 5, 'square', 'red')

Проверка столкновения

У Turtle есть готовый метод distance(x, y) — расстояние до точки. Используем его, чтобы понять, столкнулись ли два спрайта.

def is_collide(self, sprite): dist = self.distance(sprite.xcor(), sprite.ycor()) return dist < 25
🧠 Как это работает

Метод distance(x, y) возвращает расстояние между текущим спрайтом и точкой (x, y).

Мы берём координаты второго спрайта через sprite.xcor() и sprite.ycor(). Если расстояние меньше 25 — значит, спрайты почти в одной точке. Столкновение!

Что вернёт is_collide?

Спрайты на координатах. Расстояние меньше 25 — столкновение.

Полный код игры

Соберём всё, что мы разобрали, в одну программу. Здесь видно, как наследование помогает писать игру.

from turtle import * # ─── Класс-наследник Sprite ──────────────────── class Sprite(Turtle): def __init__(self, x, y, step=10, shape='circle', color='black'): super().__init__() self.penup() self.speed(0) self.goto(x, y) self.color(color) self.shape(shape) self.step = step def move_up(self): self.goto(self.xcor(), self.ycor() + self.step) def move_down(self): self.goto(self.xcor(), self.ycor() - self.step) def move_left(self): self.goto(self.xcor() - self.step, self.ycor()) def move_right(self): self.goto(self.xcor() + self.step, self.ycor()) def is_collide(self, sprite): return self.distance(sprite.xcor(), sprite.ycor()) < 25 # ─── Создаём спрайты ─────────────────────────── player = Sprite(0, -140, 10, 'triangle', 'green') captain = Sprite(0, 140, 0, 'circle', 'blue') rock1 = Sprite(-200, 0, 6, 'square', 'red') rock2 = Sprite(200, 60, 6, 'square', 'red') # ─── Управление игроком ──────────────────────── scr = player.getscreen() scr.listen() scr.onkey(player.move_up, 'Up') scr.onkey(player.move_down, 'Down') scr.onkey(player.move_left, 'Left') scr.onkey(player.move_right, 'Right') # ─── Игровой цикл ────────────────────────────── playing = True while playing: # Двигаем астероиды и отражаем от краёв rock1.goto(rock1.xcor() + rock1.step, rock1.ycor()) rock2.goto(rock2.xcor() - rock2.step, rock2.ycor()) if abs(rock1.xcor()) > 240: rock1.step = -rock1.step if abs(rock2.xcor()) > 240: rock2.step = -rock2.step # Проверяем победу if player.is_collide(captain): captain.hideturtle() rock1.hideturtle() rock2.hideturtle() captain.goto(0, 0) captain.write('Капитан спасён!', font=('Arial', 22, 'bold'), align='center') playing = False # Проверяем поражение elif player.is_collide(rock1) or player.is_collide(rock2): captain.hideturtle() rock1.hideturtle() rock2.hideturtle() player.goto(0, 0) player.write('Корабль разбился', font=('Arial', 22, 'bold'), align='center') playing = False exitonclick()
🧠 Что здесь интересного

1. Класс Sprite написан один раз — а используем его для всех объектов: игрока, капитана, астероидов.

2. Разница только в аргументах конструктора: разные x, y, shape, color — разные объекты.

3. Без наследования от Turtle нам пришлось бы писать все команды с нуля: penup, goto, speed, shape… Наследование даёт их «бесплатно».

Игровой цикл — коротко

⚠️ Важный момент

После запуска игры кликни мышкой по экрану. Иначе стрелки не будут работать: Python не «слушает» клавиатуру, пока окно не в фокусе.

Это особенность библиотеки turtle. В настоящих играх на Pygame такого нет, но у черепашки — есть.
